## 1) Is FlowForge ready for v1.0.0?

**Not quite**. You’re close. A solid **0.9-RC** is within reach by fixing the concrete items below.

### Blockers to fix for 1.0 (actionable, file-mapped)

- **Per-stage lineage emission**
  - **Edit** `modules/core/src/main/scala/com/flowforge/core/PipelineBuilder.scala`:
    - Around the stage executor (where you run sources/transforms/sinks), add:
      - `emitJobStart(namespace, jobName = s"$pipelineName/$stageName", runId)` before each stage
      - `emitJobComplete(...)` on success of that stage
      - `emitJobFail(...)` on exceptions with a summarized error string
    - Keep emissions **best-effort** (log and continue on telemetry errors).  
    - Pair with the existing **build-time** event already in place.
  - **Docs**: in `docs/operating/lineage.md`, replace `...` with a full example and screenshots for Marquez UI.  
  - **Why:** This makes “lineage by default” actually true and demo-able via Marquez Docker. :contentReference[oaicite:6]{index=6}

  - Replace placeholder `...` in Scala sources that aren’t explicit prose.  
  - In docs, remove truncations; if future work, move to `docs/archive/` or add a clear **“Planned”** section.

- **Lock DQ default and reflect it everywhere**
  - Finalize **native Spark checks** as default (great for a slim 1.0).  
  - Provide a dedicated page “**Using Deequ with FlowForge**” with exact Maven coordinates and a short, self-contained example.  
    (Deequ is maintained with Spark 3.5 artifacts — so it’s safe to document as an option.) :contentReference[oaicite:7]{index=7}

- **One end-to-end Spark example that *always* runs**

  - Include a tiny Parquet fixture and exact commands in the README for a **<10s local[*]** loop. :contentReference[oaicite:8]{index=8}

- **Versioning / release hygiene**
  - Keep `docs/public-api.md` as **“Proposed 1.0 Surface (Pre-RC)”** until you tag `0.9.0-RC1`.
  - CI: produce an RC build artifact; ensure compile-fail tests run in CI (they do), plus a Spark local smoke test.

> With those done, a credible **0.9-RC** is ready. After a short burn-in, tag **1.0.0**.

## 2) The “brutal-truth” doc vs the thesis (Scala needs a batteries-included FP toolkit)

The thesis is sound and your build is now *demonstrably* aligned:

- **Learning time low:** a single builder; Spark nouns are explicit (`Dataset`, `Encoder`, `.as[T]`). :contentReference[oaicite:15]{index=15}
- **Small, clear code:** transforms are `Dataset[T] => Dataset[T]` — testable and engine-agnostic.
- **Fast loop:** `local[*]` with kilobyte fixtures → seconds to run.  
- **Double lock:** compile-time contracts **plus** Delta constraints at sink. :contentReference[oaicite:16]{index=16}
- **Lineage blink:** run → open Marquez → see runs/datasets without glue (once you wire stage emissions, as above). :contentReference[oaicite:17]{index=17}

Do those, tag **0.9-RC**, let it cook briefly, then ship **1.0.0** with a straight face. The product’s identity is strong: **it refuses to compile lies**, then enforces truth at the table and shows its receipts in lineage.
