# FlowForge - problems not ready for v1.0.0

---

## Reality check (what still blocks a credible 1.0)

> I went file-by-file for the items below and included the exact paths so we’re not debating vibes.

### 1) Lineage “by default” is only **partially** implemented
- **Core builder:** `modules/core/src/main/scala/com/flowforge/core/PipelineBuilder.scala` emits a **build-time** event via `OpenLineageEmitter.http[IO]` inside `emitBuildEvent(...)`, but not per-stage.
- **Pipeline type:** `modules/core/src/main/scala/com/flowforge/core/types/Pipeline.scala` contains scaffolding for per-stage events (`emitStageEvent`, `executeStagesWithLineage`), **but there are literal placeholders** and truncated strings inside the methods. The current implementation would not compile as-is (e.g., split string literals like `"[OpenLineage] Emitted PIPELI\nNE..."` and `...` blocks).
- **Emitter:** `modules/lineage/.../OpenLineageEmitter.scala` has working structure (HTTP POST, JSON paylods), **but also contains `...` and a broken default URL literal** split as `htt\np://localhost:5000/...`. This is a hard blocker.

**What “done” looks like** (minimal, concrete):
- Emit **pipeline START** before execution, then **stage START/COMPLETE** around each stage, then **pipeline COMPLETE**; on exceptions, **FAIL** with a summarized message - all *best-effort* (never fail the data path on telemetry).
- Fix the broken strings and remove **all** `...` placeholders in these paths:
  - `modules/core/.../Pipeline.scala` (implement `emitStageEvent`, `executeStagesWithLineage`, fix logging)
  - `modules/lineage/.../OpenLineageEmitter.scala` (fix URL default, remove `...`, ensure `emitJob(Start|Complete|Fail)` return `F[Either[LineageError,Unit]]` and are invoked)
  - Keep `ops/marquez/docker-compose.yml` in docs; the official OpenLineage+Marquez quickstart is the right reference. :contentReference[oaicite:3]{index=3}

### 2) **Placeholders (`...`) still ship** in code and docs
- I found **64 files** with literal `...` - **11 Scala** and many docs. Some are benign (comments), some are in live code or user-facing docs.
  - Examples in Scala:  
    - `modules/core/.../Pipeline.scala` (stage emission + logs)  
    - `modules/lineage/.../OpenLineageEmitter.scala` (signature and JSON builders)  
    - `modules/connectors/.../FileSystemConnector.scala` (method bodies)  
    - `modules/examples-spark/.../UsersPipeline.scala` (class comment and top section)  
    - `modules/compile-fail-tests/.../CompileTimeContractFailSpec.scala` (mid-test truncation block)
  - Examples in docs: ADRs, `docs/operating/lineage.md`, `docs/why/compare.md`, `flowforge.g8/README.md`, and several `docs/evidence/*`.
- **1.0 cannot ship with ellipses**. If something is future work, move it to `docs/archive/` or remove from the release surface.

### 3) **DQ default vs docs** - almost aligned, but finalize
- Code comments now indicate **native Spark checks** as the **default**, with **Deequ** as **optional**. This is reasonable for 1.0 - slimmer, fewer moving parts.
- Ensure **examples and docs** match that story:
  - In `docs/quality/*`, explicitly list which checks are native (non-null, uniqueness, length/pattern) and point to a *separate page* “Using Deequ” with Maven coords (e.g., `com.amazon.deequ:deequ:2.0.11-spark-3.5`) and a short example. :contentReference[oaicite:4]{index=4}

### 4) **End-to-end example must be runnable** (no placeholders)
- `modules/examples-spark/.../UsersPipeline.scala` still contains `...` in the header and includes helper snippets not fully shown. For 1.0:
  - Input Parquet → `.as[T]` (with `Encoder[T]`) → pure `Dataset.map` transform → native DQ summary → **Delta** write → **NOT NULL / CHECK** constraints → lineage events visible in Marquez - **all in a single file, no ellipses**.  
  - Provide a tiny fixture under `modules/examples-spark/src/test/resources/...` and a README with exact commands for a **<10s `local[*]`** loop.
  - The “typed dataset requires Encoder + `.as[T]`” should be explicit in code comments. :contentReference[oaicite:5]{index=5}

### 5) **CI polish**
- `.github/workflows/ci.yml` has the right jobs, but a few strings are line-wrapped oddly (e.g., `*Eng\nineAbstractionSpec`). Verify the class names and ensure the smoke tests actually select existing suites.
- Keep `scalafmtCheckAll`, `scalafixAll`, compile-fail tests, link-check, and **one Spark local smoke** as hard gates.

## 1) Is FlowForge ready for v1.0.0?

**Verdict:** **Not yet.** You’re one small patchset away from a credible **0.9.0-RC1**. Ship RC when the items above are fixed; go 1.0 after a short burn-in.

**Release-blocking fixes (summarized):**
1) Implement per-stage OpenLineage emission and fix broken strings. (Builder + Pipeline + Emitter + docs + Marquez demo.) :contentReference[oaicite:6]{index=6}  
2) Remove/replace **all** `...` placeholders from sources and public docs.  
3) Lock **native DQ as default** and document Deequ as optional with exact coords. :contentReference[oaicite:7]{index=7}  
4) Provide **one flawless Spark example** that always runs locally and demonstrates contracts → DQ → Delta constraints → lineage. :contentReference[oaicite:8]{index=8}

## Concrete, file-mapped patch plan (short + surgical)

> This is the minimum to tag **0.9.0-RC1** confidently.

1) **Stage-level lineage (code + docs)**
   - **`modules/core/.../Pipeline.scala`**  
     - Implement `emitStageEvent` and `executeStagesWithLineage` (no `...`; fix split strings).  
     - Call `emitStageEvent("START" | "COMPLETE" | "FAIL", ...)` around each stage.  
   - **`modules/lineage/.../OpenLineageEmitter.scala`**  
     - Fix default URL string, remove `...`, ensure `postEvent` robustly handles non-2xx.  
   - **`docs/operating/lineage.md`**  
     - Replace `...` with exact commands and add 2–3 screenshots.  
   - **Reference**: OpenLineage/Marquez quickstart. :contentReference[oaicite:20]{index=20}

2) **Remove placeholders**
   - Grep for `...` and delete/replace in:  
     - `modules/examples-spark/.../UsersPipeline.scala`  
     - `modules/connectors/.../FileSystemConnector.scala` (either finish minimal surface or move to `docs/archive/`)  
     - `modules/compile-fail-tests/.../CompileTimeContractFailSpec.scala` (replace mid-test `...` with a proper failing case)  
     - `docs/**/*`, `flowforge.g8/README.md`

3) **DQ default & option**
   - **Default:** native Spark checks; ensure examples show them.  
   - **Option:** Deequ page with coords `com.amazon.deequ:deequ:2.0.11-spark-3.5` and a tiny `VerificationSuite` example. :contentReference[oaicite:21]{index=21}

4) **One flawless e2e Spark example**
   - Single file, no ellipses, tiny fixture, instructions for <10s `local[*]` loop.  
   - Explicit `Encoder[T]` + `.as[T]`, native DQ printout, Delta constraints, lineage. :contentReference[oaicite:22]{index=22}

5) **CI sanity**
   - Fix any line-wrapped test patterns; keep compile-fail suite and a Spark local smoke.

## Brutal, unvarnished bottom line

- The **idea** is excellent and the **shape** is right.  
- The **implementation** still contains placeholder code and partial lineage wiring; shipping **1.0** like this would undercut trust.  
- Remove every `...`, wire stage-level lineage, lock DQ default, and give the world a one-file Spark example that truly runs in seconds. Then tag **0.9-RC**; after a short shakedown, you can ship **1.0** with a clear conscience.
