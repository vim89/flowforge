# FlowForge v1.0.0 — Single-Document Cut Plan (Do-This-Ship-That)

This is the **one canonical checklist** to take FlowForge from “promising” to **v1.0.0**. It’s opinionated, narrow, and shippable. No detours. No vibe-driven yak-shaving. Just crisp steps, ownership, and pass/fail gates.

---

## 0) Release north-star (what v1.0.0 *is*)

**Golden Path**: one **end-to-end, contract-first** data pipeline on **Spark 3.5 LTS**, with:

* **Contracts as code** → generate **data-quality checks** (Deequ)
* **Physical constraints** on **Delta Lake** (NOT NULL + CHECK)
* **OpenLineage events** (job/run + stage-level) emitted to Marquez (or noop toggle)
* **g8 archetype** that boots, compiles, runs the demo **in 10 minutes**

Pin runtime to **Spark 3.5.6** for compatibility and stability; call out Spark 4.0.x as “Tech Preview,” not the default. ([Apache Spark][1])
Delta Lake supports **NOT NULL** and **CHECK** constraints (no native UNIQUE) — enforce uniqueness via Deequ and/or merge-dedupe, not table constraints. ([Delta Lake][2], [delta.io][3])
Use **Deequ** for DQ (Spark 3.5 line has published artifacts). ([Maven Repository][4], [Maven Central][5])
Use **OpenLineage** spec & Marquez receiver for lineage. ([OpenLineage][6], [GitHub][7])

> **Definition of Done (DoD):** a new user can `sbt new`, paste a 30-line config, and see: **Contracts compiled ✅**, **DQ checks evaluated ✅**, **Delta constraints applied ✅**, **OpenLineage START/COMPLETE + stage events ✅** — in under 10 minutes wall-clock on a laptop.

## 1) Scope freeze (what ships vs not)

**IN v1.0.0**

* Engine: **Spark 3.5.6** (Scala 2.13 target), batch mode + small streaming demo optional. ([index.scala-lang.org][8])
* Modules: `core`, `contracts`, `builder`, `dq-deequ`, `delta-integration`, `lineage-openlineage`, `archetype (flowforge.g8)`, `docs`.
* Effects: **effect-polymorphic core** with one **blessed example** (either Cats-Effect *or* ZIO) in docs. Keep core **F\[\_]-agnostic**; don’t leak `IO` anywhere in `main` sources.

**OUT / LATER**

* Flink runner, Kafka runner, Beam/Scio adapters, Spark 4.x as default, complex CDC (SCD2), fancy GADTs for pipeline phases, catalog integrations beyond the basics. (List them under **1.1 Roadmap** with dates.)

## 2) Version matrix (pin these; avoid “latest”)

* **Spark**: 3.5.6 default; 4.0.1 “tech preview” profile (separate CI job; allowed to fail). ([Apache Spark][1])
* **Delta Lake**: latest compatible with Spark 3.5 (document tested combo in `docs/compat.md`). Constraints we rely on: **NOT NULL**, **CHECK**. No UNIQUE. ([Delta Lake][2])
* **Deequ**: `2.0.x-spark-3.5` artifact (confirm in `build.sbt` and docs). ([Maven Central][5])
* **OpenLineage / Marquez**: pin minor versions and note spec compatibility (Marquez keeps backward compatibility for spec versions). ([GitHub][7])

## 3) P0 cleanup (blockers you must clear before anything else)

1. **Purge placeholders**

    * Forbidden in `src/main/scala`: `...`, `???`, half-written statements.
    * Gate with a script: `grep -R --line-number -E '\.\.\.|^\s*\?\?\?$' modules/*/src/main/scala && exit 1`.

2. **Effect purity**

    * Zero `cats.effect.IO` imports in **core** where code is F-polymorphic.
    * No `unsafeRunSync` anywhere.
    * Provide **adapters** in `examples` to *instantiate* F (CE or ZIO).

3. **Lineage emitter**

    * Implement `OpenLineageEmitter[F]` with `F.delay` (or `Async[F]`) + **http backend via typeclass**; add `NoopEmitter[F]`.
    * Add `pipeline.emitStageEvent[F]` wired through builder, not hard-coded effect.

4. **CI YAMLs parse & run**

    * Remove ellipses/cut lines; validate with `yamllint` locally.
    * Jobs order (see §8 CI/CD).

5. **flowforge.g8** must compile and run **green** from a fresh folder.

**Exit gate**: `sbt +compile` passes, `scalafmtCheckAll`/`scalafix --check` pass, `dq` and `lineage` modules compile, archetype boots.

## 4) Golden Path demo (the product story you’re selling)

**Scenario**: `raw_users.csv` → typed case class `User` enforced by **Contract** → DQ checks via **Deequ** → persisted to **Delta** with **NOT NULL**/**CHECK** → **OpenLineage** events emitted.

**Contract (sketch)**

* `id: NonEmptyString`, `email: String Refined MatchesRegex[Email]`, `age: Int Refined Interval.Closed[18,120]`
* SLA/freshness metadata + owner fields (not enforced at runtime, but visible in docs/lineage).

**DQ mapping** (contract → Deequ analyzers):

* `nonNull(id)`, `nonNull(email)`, `compliance("email_like", "email RLIKE ...")`, `compliance("age_range", "age BETWEEN 18 AND 120")`, `uniqueness(id)` (via Deequ; **not** Delta). ([Maven Repository][4])

**Delta constraints** (physical):

* `NOT NULL (id, email, age)`, `CHECK (age BETWEEN 18 AND 120)`. Note: **no UNIQUE** in Delta; communicate clearly in docs. ([Delta Lake][2])

**Lineage**

* Emit **START** and **COMPLETE** for the pipeline, and **stage events** for `read_raw`, `dq_validate`, `delta_write`.
* Provide a `--lineage=noop|marquez` switch.

**Commands (developer journey)**

```bash
# 1) create from template
sbt new flowforge/flowforge.g8
cd my-pipeline

# 2) run the golden path
sbt "runMain com.myco.users.PipelineMain --input data/raw_users.csv --out ./tmp/delta/users --lineage=noop"

# 3) observe outputs
cat target/flowforge/run.log | grep -E "Contracts compiled|Deequ checks|Delta constraints|OpenLineage"
```

**Acceptance test**: An `it:test` asserts:

* contract derivation compiled (compile-time test)
* Deequ returned the expected `CheckStatus.Success`
* Delta table has NOT NULL/CHECK metadata
* Lineage calls executed (or were no-op if configured)

## 5) Effect policy (clear and boring)

* **Core**: all public builders/DSLs are **parametric in `F[_]`** with the minimal needed typeclasses (`Sync` / `Async`, `Clock`, `Logger`).
* **IO boundaries**: only in `modules/examples/*` or `modules/integration/*` mains.
* **Error model**: typed ADTs for **domain** errors; use `ValidatedNel` for *aggregating* contract/DQ failures; use `EitherT`/`ZIO` equivalents only at edges.
* **Adapters**: provide `cats-effect` instance and a **ZIO example** in docs, but ship only **one** default in the archetype to reduce starter friction.

## 6) Data Quality integration (Deequ)

* Pin Deequ **Spark 3.5** artifact and document exact coords. ([Maven Central][5])
* Build **contract → deequ** mapper (nonNull, isComplete, compliance, uniqueness, pattern).
* Add **profiles**: “strict” (fail on any check), “warn” (log only).
* Emit a **Deequ JSON summary** artifact under `target/flowforge/dq/`.

---

## 7) Physical constraints (Delta)

* Map **contract** to Delta writers with **NOT NULL** and **CHECK**. Unique is *advisory only* (document that Delta can’t enforce it natively). ([Delta Lake][2])
* Add a helper: `DeltaEnforcer[F].ensureConstraints(tablePath, constraints)` that (a) creates or (b) alters table with constraints as needed, versioning considered.
* Include a troubleshooting doc on constraint violations (Delta transaction aborts). ([Databricks Documentation][9])

---

## 8) Lineage (OpenLineage)

* Implement `OpenLineageEmitter[F]` with pluggable transport (HTTP).
* Schema: jobs, runs, datasets; per-stage events include input/output datasets.
* Add **toggle**: `lineage.mode=noop|openlineage` + endpoint config.
* Provide a Marquez docker-compose for local testing in `ops/`. ([OpenLineage][10])

## 9) Archetype (flowforge.g8)

* `sbt new` yields a **single module** project with:

    * `Contract.scala`, `PipelineMain.scala`, `dq.conf` (sample checks), `delta.conf` (constraints), `application.conf`
    * **Sample dataset** under `data/` and **expected output** text
    * A **README.md** with the exact 4 commands to success
* **Template test** in this repo: generate into `target/smoke/myproj`, run `sbt test` inside; fail CI if it doesn’t pass.

---

## 10) CI/CD (GitHub Actions)

**Jobs & order (all must pass):**

1. **lint**: `scalafmtCheckAll`, `scalafix --check`, `sbt headerCheck`
2. **core-compile**: `sbt +compile` (JDK 11/17 matrix)
3. **unit-tests**: `sbt test` (parallel per module)
4. **it-golden-path**: spins a local Spark session, runs the demo; asserts artifacts (`dq.json`, lineage logs, Delta constraints)
5. **archetype-smoke**: `sbt new` → `sbt test` in generated project
6. **docs-mdoc**: build docs; link check
7. **spark-4-tech-preview**: *allowed to fail* (keeps us honest on 4.0.x). ([Apache Spark][1])

**Quality gates:**

* Scripted checks: **no `...`/`???`** in `src/main/scala`.
* No `IO` imports in F-polymorphic modules.
* `dq` and `delta` modules must compile with Spark 3.5.6.

* **Concepts** — Contracts, DQ mapping, Constraints, Lineage, Effects
* **How-Tos** — Add a new check; add a new constraint; emit lineage to Marquez; toggle noop emitter

## Why this plan gets you a real 1.0 (and not another “almost”)

* It **narrows scope** to one immaculate path (Spark 3.5 LTS), where the ecosystem is stable and documented. ([Apache Spark][14])
* It **ties the USP to reality**: a **single contract** drives **DQ**, **Delta constraints**, and **Lineage**, with copy-paste runnable evidence.
* It **codifies DX**: the archetype guarantees a 10-minute success loop.
* It **admits limits** (no UNIQUE in Delta) and routes them through DQ instead of pretending otherwise. ([Delta Lake][2])

If you execute the checklists above as written, you’ll have a coherent, opinionated **v1.0.0** that’s small, fast to learn, and actually useful — the sort of thing teams adopt because it works on Monday morning, not just in a blog post.
