# [ARCHIVED] FlowForge Contracts-as-Code: Compile-Time Gates + Build-Time Physical Validation

> Superseded by ADR-011 (Contracts Compile-Time & Build-Time Gates, CI-first) and ADR-021 (Contracts Source of Truth and Codegen).
> Note: No sbt AutoPlugin is maintained; the authoritative gate is CI (GitHub Actions Forms + validation-cli). Case classes and `.avsc` are generated in CI from Forms.

Updated: 2025-09-03
Status: Critical design - required for MVR→MVP
Owners: Framework + Core + Templates

## Purpose
Guarantee downstream developers discover schema mismatches before running any code by combining:
- Compile-time gates: code cannot compile if pipeline types don’t match published contracts.
- Build-time physical validation: compile depends on checks that actual tables/files match the contracts.
- Platform gates: optional runtime constraints to prevent bad data landing or promotion.

Result: “Won’t compile if your schema doesn’t match” holds for code-vs-contract, and your local build/CI fails fast if upstream physically writes bad data.

## Guiding Principles
- Contracts are code: versioned, generated into the repo as types + witnesses.
- Engines stay pure where possible: Spark transforms are pure; external IO is effectful.
- Typed-only public API: untyped builders are deprecated and fail CI.
- Checks shift left: most failures occur at compile/build time.

## Scope & Non‑Goals
- In-scope: Scala 2.13 baseline; Cats-Effect/ZIO; Spark first; Delta/Hive/GCS Parquet.
- Out-of-scope (initial): Automated contract publication tooling for upstream teams; full schema registry admin UI.

## Architecture Overview
1) Compile-time gates (types ↔ contracts)
- Codegen generates case classes and type witnesses (TypedSource/TypedSink) from contract definitions.
- PipelineBuilder2 exposes only typed endpoints:
  - addTypedSource[C, R](src: TypedSource[R])(implicit LabelledGeneric.Aux[C, R])
  - addTypedSink[R](sink: TypedSink[R])(implicit SchemaEq[Out, R])
- If witnesses cannot be derived, compilation fails with a readable error.

2) Build-time physical validation (contracts ↔ storage)
- A GitHub Actions workflow materializes contracts and runs `validation-cli` to compare physical schemas vs contracts; PRs fail on mismatch.

3) Platform gates (storage ↔ invariants) [optional]
- Delta/Hive constraints (NOT NULL, CHECK) and/or DLT expectations with fail/drop semantics.
- Catalog-level “data contracts/assertions” in DataHub/OpenMetadata for continuous drift detection.

## Library & Tooling Choices

Baseline (recommended):
- Cats + Cats-Effect or ZIO (already present).
- Schema formats: Avro (primary), Protobuf optional.
- Codegen:
  - Avro: sbt-avrohugger (Scala 2.13) or avro4s codegen mode. We prefer explicit codegen to eliminate runtime reflection.
  - Protobuf: ScalaPB (sbt-protoc) if a team mandates Protobuf contracts.
- Type witnesses:
  - Scala 2.13: shapeless LabelledGeneric (already used in the repo) for field-name/type alignment.
  - Scala 3 (future): prefer Mirrors + inline compile-time checks to reduce 3rd-party macro surface.
- Spark typing (optional module): Frameless for compile-time checked column/project/union/select. Not required for the core promise; keeps transforms safer when used.
- Physical schema readers:
  - Delta: DeltaTable APIs / DESCRIBE DETAIL.
  - Hive/Metastore: Spark catalog listColumns/describeTable.
  - Parquet: Spark read schema or Parquet footer (no data scan); fast mode for CI.
- Registry (optional but encouraged): Confluent Schema Registry via REST; sbt-schema-registry plugin to fetch subjects/versions.

Why/Why not shapeless & frameless?
- shapeless: pragmatic for Scala 2.13 to derive LabelledGeneric witnesses today; we already depend on it. Migration path: drop it when Scala 3 is primary and use Mirrors.
- frameless: excellent safety for Spark operations but can lag engine versions; make it optional in `flowforge-typed-spark` so adopters can opt in without blocking core upgrades.
- We keep core minimal: Cats/ZIO + standard Scala; type witnesses are a thin layer. Frameless is an add-on, not a requirement.

## API Sketch

```scala
// Generated by codegen per contract (Avro/Proto/etc.)
final case class SalesV12(...)
final case class SalesCuratedV5(...)
object Contracts {
  type SalesV12Repr = /* Labelled HList witness (Scala 2) or Mirror (Scala 3) */
  type SalesCuratedV5Repr = /* witness */
  implicit val srcWitness: LabelledGeneric.Aux[SalesV12, SalesV12Repr] = ???
  implicit val tgtWitness: LabelledGeneric.Aux[SalesCuratedV5, SalesCuratedV5Repr] = ???
  val SalesSource: TypedSource[SalesV12Repr] = TypedSource(/* metadata */)
  val SalesSink:   TypedSink[SalesCuratedV5Repr] = TypedSink(/* metadata */)
}

// FlowForge core types
trait SchemaEq[A, R]
object SchemaEq {
  implicit def eqFromLabelledGeneric[A, R](implicit L: shapeless.LabelledGeneric.Aux[A, R]): SchemaEq[A, R] = new SchemaEq[A, R] {}
}

final case class TypedSource[R](underlying: DataSource)
final case class TypedSink[R](underlying: DataSink)

// PipelineBuilder2 gates
def addTypedSource[C, R](src: TypedSource[R])(implicit L: LabelledGeneric.Aux[C, R]): Builder[Unit, C]

def addTypedSink[R](sink: TypedSink[R])(implicit Ev: SchemaEq[Out, R]): Builder[In, Unit]
```

Compile failure example:
- If pipeline’s `Out` doesn’t match `SalesCuratedV5Repr`, `SchemaEq[Out, SalesCuratedV5Repr]` cannot be resolved; scalac reports a helpful error message (we add `@implicitNotFound` to `SchemaEq`).

## Contract Artifacts Delivery (no local codegen)

Recommended path for non-developers and simpler DX: generate contract artifacts centrally in CI and publish a versioned "contract SDK" that application teams depend on. No sbt plugin or local codegen required.

Flow:
- Authoring (non-technical): Data Stewards/Modelers use a UI (Registry UI, Data Catalog UI, or an internal Contract Portal) to define/update contracts (Avro/Proto/JSON Schema) with descriptions and constraints.
- Storage of truth: Contracts live in a Git repo (contracts.git) in human-readable form (.avsc/.proto/.json) with metadata YAML. The portal commits PRs on behalf of authors; approvals apply governance.
- CI on merge:
  1) Validate + lint contracts; run compatibility checks against Schema Registry; block breaking changes without approval.
  2) Generate Scala types + TypedSource/TypedSink witnesses and package them into a versioned JAR per domain (e.g., `com.acme.contracts:sales-contracts_2.13:1.2.3`).
  3) Publish the JARs to the artifact repository and update the Registry subjects to the new version.
  4) Notify subscribers (Slack/Webhook) and update the data catalog (e.g., DataHub/OpenMetadata) with lineage and schema docs.
- Consumption: Downstream code depends on the contract SDK JAR; `PipelineBuilder2` accepts only the typed endpoints from that SDK, enforcing compile-time gates without any local code generation.

This keeps authoring non-technical, centralizes governance, and still delivers compile-time guarantees to all consuming repos.

## sbt AutoPlugin Sketch (flowforge-contracts-guard)

Settings (typical):
- `ffContract.sourceSubject`, `ffContract.targetSubject` (registry subjects) OR
- `ffContract.sourceSpec`, `ffContract.targetSpec` (local Avro/Proto files)
- `ffPhysical.source` (gcs://... or delta table identifier), `ffPhysical.target`
- `ffPolicy.compatibility` (BACKWARD/FULL, etc.)

Tasks:
- `ffGenerateContracts`: fetch contracts → generate case classes + TypedSource/TypedSink + witnesses
- `ffVerifySourcePhysical`: fetch physical schema (fast) → compare vs source contract
- `ffVerifyTargetPhysical`: fetch physical schema → compare vs target contract
- `ffVerifyRegistryCompatibility`: optional registry compatibility check

Wiring (if you choose local codegen):
- `Compile / sourceGenerators += ffGenerateContracts.taskValue`
- `Compile / compile := (Compile / compile).dependsOn(ffVerifySourcePhysical, ffVerifyTargetPhysical).value`

## Physical Schema Comparison
- Delta: `DeltaTable.forPath(...).toDF.schema` then normalize to a canonical model (name, type, nullable, metadata); compare to contract.
- Hive: `spark.sessionState.catalog.listColumns/db.table`; canonicalize and compare.
- Parquet (GCS): read parquet footer or `spark.read.schemaOnly(...).schema`; no data scan.
- Comparison policies: exact match, superset (allow nullable extras), or evolution rules; express via settings.

## Developer Workflow (Downstream Scenario)
1) Choose source/target contracts (subject+version or files). Run `sbt compile`.
2) Codegen emits typed endpoints and witnesses; you author transforms with type safety.
3) Compile step triggers physical checks; if upstream landed incorrect data, compile fails with a clear diff.
4) CI runs the same checks + optional registry compatibility jobs and canary validations.

## Error Messages & DX
- Use `@implicitNotFound` on `SchemaEq` to produce clear compile errors.
- On physical mismatches, render a compact diff (missing fields, type changes, nullability changes) with remediation hints.
- Provide quick-fix sbt hints (e.g., which subject version to pin or what PR to block upstream).

## Migration Strategy
- Phase 1 (MVR): Keep legacy `PipelineBuilder` but mark deprecated; add scalafix rule to block new usage.
- Phase 2: Make typed endpoints the only public path; CI fails on legacy usage.
- Phase 3: Default templates (g8) use contracts-first and wire the sbt plugin.

## Risks & Mitigations
- Registry or storage not reachable during compile → allow `ffOffline = true` mode that skips physical checks locally but never in CI.
- Frameless lag vs Spark releases → keep it optional; core remains dependency-light.
- Schema evolution complexity → start with strict equality or “backward” policy; document evolution playbooks.

## Concrete Implementation Plan
1) Core types: `TypedSource`, `TypedSink`, `SchemaEq`, `@implicitNotFound` messages; gate `PipelineBuilder2`.
2) Codegen module: sbt AutoPlugin; Avro/Proto code generators; emit witnesses and typed endpoints.
3) Physical validators: Delta/Hive/Parquet readers; canonical schema model + diff renderer.
4) CI: add tasks to PR pipeline; block merge on failures.
5) Templates: new g8 that asks for source/target contracts and pre-wires everything; sample project compiles in <2 minutes.

## Library Matrix (Decision)
- Must:
  - Cats, Cats-Effect or ZIO (already in repo)
  - shapeless (Scala 2.13 only; remove when Scala 3 primary)
  - Avro codegen (sbt-avrohugger or avro4s codegen) or ScalaPB for Protobuf
- Optional:
  - Frameless (typed Spark operations) in `flowforge-typed-spark`
  - Schema Registry plugin (if org uses Confluent)
  - zio-schema (for schema diffs/messages)

Rationale: Keep core minimal and stable; use well-recognized tools for codegen and optional typing layers. This satisfies CONTRIBUTING.md principles without over-engineering.
